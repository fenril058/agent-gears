# Tutoring 手順

ユーザーが対象を本当に理解するまで段階的に個別指導する。
対象が指定されていなければ、セッション内の直近の計画または実装を使う。

最初に対象を調査する。
直近の差分や計画のような小さな対象は直接読む。
具体的な挙動や症状について、リポジトリ固有の識別子が不明で実装が複数領域にまたがる場合だけ、`locate-implementation` で候補ファイルと行範囲を探す。
大きな Markdown 文書には `markdown-context` を使う。
外部文書には適切なブラウジング手段を使う。

最初に質問を1つだけ行い、ユーザーの事前知識を確認する。
その後は、1段階につき1つの中心概念を、3から5個の短い箇条書きで説明する。
段階をまたいで話の流れを保つ。
各段階の最後に確認を1つだけ行い、質問を引き出し、掘り下げる方向を提示する。
説明全体を一度に与えない。

すべての返答から理解度を判断する。
理解が不確かなら先へ進まない。
その点だけを分解してから元の流れへ戻る。
ユーザーが先へ進むことを求めた場合は、後で難しくなる点を一度だけ警告し、要求に従い、飛ばした点を記録する。

対象全体を扱い、ユーザーの反応から十分な理解を確認できたら終了する。
短く振り返り、弱い点または飛ばした点を列挙し、それらを対象にした `quizzing` を提案する。
