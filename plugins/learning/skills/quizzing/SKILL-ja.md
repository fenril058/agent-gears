# Quizzing 手順

ユーザーが対象を自分の言葉で説明できるようになるまで質問する。
対象が指定されていなければ、セッション内の直近の計画または実装を使う。

最初に対象を調査する。
直近の差分や計画のような小さな対象は直接読む。
大規模または不慣れなコードベースを意味的に広く探索する場合は `fast-search` を使う。
大きな Markdown 文書には `markdown-context` を使う。
外部文書には適切なブラウジング手段を使う。

自由回答の質問を一度に1つだけ行う。
次の3つの観点を組み合わせる。

- なぜ: 設計上の判断と退けた代替案。
- どのように: 振る舞い、データフロー、構造。
- もし: 変更の影響とエッジケース。

計画では「なぜ」を、コードでは「どのように」と「もし」を多めにする。
ユーザーが回答を試みる前に答えを明かさない。

各回答の後で次を行う。

- 正しい点を確認する。
- 間違いを訂正する。
- 不足を補う。
- 弱い点を掘り下げる。
- 十分に理解できている点は先へ進む。

対象全体を扱い、ユーザーの回答が十分になったら終了する。
後で復習できるよう、残った弱点をまとめる。
