# ネットワーク接続エラーを調べる

## エラーを分類する

- エラー全文を読み、失敗したホスト名と操作を特定する。
- 失敗したコマンドと同じ実行環境から、そのホスト名を名前解決でき、接続できるか確認する。
- DNS、接続、TLS の失敗と HTTP 応答を区別する。ネットワークエラーだけでは、認証情報が無効であることも、接続先サービスが停止していることも判断できない。
- 1つのホスト名または実行環境での失敗を、すべての接続先へ一般化しない。
- `gh auth status` などのクライアント認証確認は、そのクライアントが接続先に到達できることを確認してから行う。接続できない環境では認証確認も不確かになる。

## 許可された実行環境を使う

- 実行環境が必要な外向き接続を遮断している場合は、同じ環境から同じ要求を繰り返さない。
- 必要な接続先へのアクセスが許可された実行環境で操作を再試行する。その環境が使えない場合は、作業を妨げている制限を報告する。
- 認証・設定の問題を示す根拠があり、変更が許可されている場合を除き、認証情報、クライアント設定、sandbox の通信設定を変更しない。

## 結果を確認する

- 実行環境を変えた後、元の操作を再実行して結果を確認する。
- 接続先が認証または権限エラーを返した場合は、該当する認証情報と scope を確認する。
- 調査中に認証情報を表示したり、コピーしたりしない。
