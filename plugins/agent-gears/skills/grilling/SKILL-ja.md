# Grilling 手順書

計画・決定・アイデアのあらゆる側面について、共通理解に達するまでユーザーにインタビューする。
決定木の各分岐を降りながら、決定間の依存関係を1つずつ解決する。

ルール:

- 質問は**一度に1つ**。各問への回答を待ってから次に進む。
  複数の質問を同時にぶつけると相手を混乱させる。
- 各質問には**自分の推奨案**を添える。
- **事実**は環境(ファイルシステム、ツール、git履歴など)を探索して自分で調べる。ユーザーに聞かない。
  **決定**はユーザーのものであり、1つずつ提示して回答を待つ。
- ユーザーが「共通理解に達した」と確認するまで、計画に着手しない。

## 固まった端から記録する

痕跡を残さない grilling はセッションの終わりとともに蒸発する。
そこでインタビューを進めながら、セッションより長生きする2つを書き留める。どちらも `domain-modeling` が担当する。

- **語が確定した瞬間** → `CONTEXT.md` の用語集へ。
- **覆しにくく、文脈なしでは意外で、本物のトレードオフの結果である決定** → ADR へ。3条件すべてを満たすときだけであり、多くのセッションでは0本か少数である。

最後にまとめず、その場で書く。
長いインタビューで余力が尽きるのは、まさにその「最後」だからである。

セッションが生んだそれ以外——採った方針、退けた代替案、残作業——は、終了時に `conversation-context-export` へ回す。

## 関連スキル

- **domain-modeling**: 記録層。この skill が供給する用語集と ADR を担当する。
- **spec-ambiguity-audit**: 書かれた仕様書のギャップを安価モデルの素読みで監査する。
  grilling はその対話版で、未決定事項をユーザーと直接解決する。
- **conversation-context-export**: 共通理解に達したら export し、次セッションに決定を引き継ぐ。
