# GitHub CLI のネットワークエラーを調べる

## 接続と認証を切り分ける

- ネットワーク障害か認証障害かを判断する前に、エラー全文を読む。
- DNS エラーや接続エラーは GitHub が HTTP 認証応答を返す前に起きるため、トークンが無効だとは限らない。
- 失敗したコマンドと同じ実行環境から `api.github.com` を名前解決でき、接続できるか確認する。
- その環境から GitHub に接続できない場合、`gh auth status` の結果だけで認証状態を判断しない。

## ネットワークが使える環境で再試行する

- 実行環境から GitHub を名前解決または接続できない場合は、許可された外部通信が使える実行環境で依頼されたコマンドを再試行する。
- ネットワークが遮断されていると確認した後は、同じ環境で再試行を繰り返さない。
- 接続確認または到達可能な GitHub 応答によって認証・権限の問題が判明しない限り、認証情報や GitHub CLI の設定を変更しない。

## 結果を確認する

- 実行環境を変えた後、元のコマンドを再実行して結果を確認する。
- GitHub が認証または権限エラーを返した場合は、`gh auth status` と必要な token scope を確認する。
- 調査中に token を表示したり、コピーしたりしない。
