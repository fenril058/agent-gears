# Model Routing (委譲ポリシー)

**委譲は既定の動作ではない。**
ユーザーが求めたとき、または課金形態からティア分割が実際に効くときに検討する。
どちらの場合もホストの指示が起動を許可している必要があり、費用上の理由はホストの指示を上書きしない。

「委譲できる仕事を委譲してトークンを削る」という以前の方針には、2つの条件が付く。

- ホスト側が、求められていないサブエージェントの起動を抑制する方向にある。
  spawn は cold start になり、メインセッションが既に持っている文脈を再導出するためである。
  自発的に委譲する前にホスト自身の指示を確認する。
- 節約はティアごとにトークン単価が違うことを前提にしている。
  定額プランでは制約が単価ではなくレート制限なので、安いティアは何も買わず、cold start の分だけ余計にかかる。
  トークン従量課金なら節約は実在し、ホストが許可する場合は自発的な委譲にも意味がある。

つまり以下の基準は、委譲が選択肢に上がったあとの「どう委譲するか」を定めるもので、
自分から委譲に手を伸ばすかどうかを定めるものではない。

## 委譲してよい作業

- 作業を一文で明確に指示でき、出来上がりの正否が機械的に判定できる。
- ファイルをまたぐ探索だが、欲しいのは結論(該当箇所/要約)だけ。
- 同じ操作の反復で、量が多い。

## メインセッションに残す作業

- 何をすべきか自体を決める段階(設計・方針)。
- 失敗のコストが高く、判断に文脈の含みが要る。
- 短くて委譲のオーバーヘッドの方が高い。「機械的だから」だけを理由に些末なタスクを委譲しない。
- セカンドオピニオン。これは判断の仕事であり強いモデルに置く。
  `subagent-consultation` を見よ。安ティアの委譲先には回さない。

## 依頼文の書き方

委譲が読み取りの重い中間文脈をメインセッションの外に出せるのは、委譲先が読んだものの
全文転記ではなく**結論だけ**を返す場合に限る。

次の3点を必ず埋める。埋めないと委譲先が裁量で補い、結果がぶれる。

- **対象範囲**: 何を / どのファイル群を扱うか。除外条件も書く。
- **期待する成果物**: 何が出来上がっていればよいか。
- **返してほしい形**: 差分 / 出典付き要約(`path:line`) / 変更ファイル一覧 のどれか。

委譲先には結論だけを返すよう指示し、大きな Markdown は全文でなく節単位(mdidx)で
読ませる。委譲先自身の文脈も安く保つ。

## プラットフォーム実装

### Claude Code

Claude Code はメインセッションのモデルを skill/hook から自動切替できないので、委譲は
Task/Agent ツールで明示的に行う。
ユーザーが委譲を求めた場合、または上記の従量課金条件でホストが自発的な委譲を明示的に許可する場合だけ起動する。
本リポジトリは委譲先 agent を2つ同梱する(`agents/`
で定義、`~/.claude/agents/` に配置)。`subagent_type` に名前を指定して呼ぶ。

- **`bulk-edit`(安ティア)**: 指示が明確で判断の要らない作業 —
  一括リネーム、整形、定型の文字列置換、テンプレ展開、反復編集。
- **`search`(中ティア)**: コードベース探索・要約・調査(fastcontext 実行含む)、
  中規模で筋の見えている実装。

委譲文の例(bulk-edit へ一括リネーム):

> subagent_type: bulk-edit
> 対象範囲: リポジトリ全体の識別子 `foo_bar`(単語境界一致のみ、部分一致・コメント内は除外)
> 作業: `fooBar` へ機械的に置換。挙動は変えない。曖昧な箇所は置換せず保留して報告。
> 返す形: 変更ファイル一覧と置換件数の要約(差分は不要)。

委譲文の例(search へ調査):

> subagent_type: search
> 対象範囲: レート制限の実装箇所(ミドルウェア/デコレータ/設定/カウンタ)
> 期待する成果物: 方式・制限値・適用範囲・主要ファイルの要約
> 返す形: 出典付き(`path:line`)の簡潔な要約。コード全文転記は不要。

### Codex

Codex にも同じ構造が別の名前で揃っているので、ティアの切り分けはそのまま通る。
agent の定義は `agents/*.md` ではなく `agents_dir` 設定(`$CODEX_HOME/agents/*.toml`)に置き、
起動は Agent ツールではなく subagent を立てるツール、実行中の確認は `/agent` で行う。
ビルドが対応していれば agent ごとのモデル上書きもある。
ツール名はビルドによって異なるので、このファイルではなく実際の Codex 側から読み取ること。
Claude Code 固有なのは frontmatter の `model:` というキー自体だけである。
