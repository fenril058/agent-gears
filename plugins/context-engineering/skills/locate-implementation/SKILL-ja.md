# Locate Implementation (fastcontext)

`fastcontext` を、時間を制限したリポジトリ内のコード位置探索に使う。
探索用ツールはソースファイルを編集しないが、CLI は checkout に対して読み取り専用ではない。
`--traj` を指定しなければ、現在の checkout に `.fastcontext/` を作成し、時刻を含む名前の JSONL trajectory を書く。
設定済みのエンドポイントへリポジトリ内容を送信する可能性もある。
メインエージェントが確認する候補ファイルと行範囲だけを返させ、設計や最終判断を委ねない。

## 適用条件

次の条件をすべて満たす場合だけ `fastcontext` を使う。

- 問いが具体的な挙動、障害の症状、または実行経路を自然言語で示している。
- リポジトリ固有の識別子・シンボル・パスがまだ分からず、1〜2回の対象を絞った Grep では経路を特定しにくい。
- 実装が複数のファイルまたは領域にまたがると見込まれる。
- 有用な成果物が、候補ファイルと行範囲の簡潔な一覧である。
- リポジトリが大規模または不案内で、探索中の大量の読み取りをメイン文脈から分離する価値がある。

一つでも満たさなければ Grep、Glob、必要ファイルの直接読み取りを使う。

次の用途には `fastcontext` を使わない。

- 既知ファイル、既知シンボル、エラー文字列など、正確な検索語がある。
- アーキテクチャの把握、設計評価、実現可能性の調査、issue の優先順位づけ。
- リポジトリ全体の状態や品質の評価。
- issue、Web ページ、実行時状態、ログなど、リポジトリ外の根拠が必要な問い。
- 小規模なリポジトリ、または1〜2回の検索と読み取りで答えられる問い。

## 設定

`fastcontext` は OpenAI 互換 API を使い、次の環境変数を読み、`FC_` 付きの名前を優先する。

- `FC_API_KEY` (`API_KEY`)
- `FC_MODEL` (`MODEL`)
- `FC_BASE_URL` (`BASE_URL`)

認証情報はリポジトリや Nix store に置かない。
Ollama では、空でないダミーの鍵と `http://localhost:11434/v1` のようなベース URL を使う。

## エンドポイントの分類と許可

`fastcontext` で API を呼び出す前に、`FC_BASE_URL` が空でなければその値を使い、空なら空でない `BASE_URL` を effective base URL とする。
どちらにも空でない値が無ければ、エンドポイントを判定不能に分類する。
分類のためにネットワーク要求、DNS 名前解決、`fastcontext` の probe を実行しない。
API key、認証 header、環境変数の無差別な一覧を表示しない。
標準に準拠したローカルの URL パーサーで文字列を解析し、URL の userinfo と port を除き、IPv6 literal の角括弧も除いた正規化済み hostname を使う。
文字列を目視で切り出したり、区切り文字で分割したりして host を決めない。
URL の値をコマンドライン引数に含めたり、コマンドへ展開したりしない。
サブプロセスで解析する場合は、`FC_BASE_URL`、次に `BASE_URL` をプロセス内で読み、そこで最初の空でない値を選び、scheme、正規化済み hostname、port だけを出力する。
該当するパーサーを利用できない場合や解析に失敗した場合は、判定不能に分類する。
解析済み URL では userinfo は host とは別の要素としてその前にあるため、`http://localhost@collector.example.com/v1` の host は `collector.example.com` である。

URL 文字列だけからエンドポイントを分類する。

- **Loopback:** 解析した host が大文字と小文字を区別せず `localhost` と完全一致するか、IPv4 アドレスの `127.0.0.0/8` に含まれるか、IPv6 アドレスの `::1` である。
- **非 loopback:** URL から host を確定でき、その host が loopback ではない。プライベートネットワーク、VPN、LAN 内の IP アドレスも非 loopback とする。
- **判定不能:** URL が無い、URL を解析できない、または host を確定できない。

`0.0.0.0` と `::` は未指定アドレスであり、loopback アドレスではないため、非 loopback に分類する。
hostname を名前解決したり、その IP アドレスが loopback だと推測したりしない。
loopback endpoint では、外部へのデータ送信に関する追加の許可を必要としない。
この免除は、転送や redirect を含む設定済みローカルエンドポイントの挙動を信頼する運用上の判断である。
通信やリポジトリ内容が端末内に留まることを技術的に保証するものではない。
非 loopback または判定不能な endpoint では、最初の API 呼び出しより前に次の開示と許可取得を完了する。
送信先の scheme、host、port だけを示す。
port は明示された値を使い、明示されていなければ既知の scheme の標準 port を使う。
確定できない値には「不明」と記す。
path、query、userinfo、認証情報、API key は表示しない。
リポジトリ内容が送信される可能性と、API の使用または課金が発生する可能性も伝える。
この開示を含む明示的な質問を会話内で行い、ツールを呼び出す前に利用者の回答を得る。
ツール呼び出し時のコマンド承認プロンプトは、この許可とは扱わない。

この許可を得られるのは、利用者と直接会話できるセッションだけである。
利用者と直接会話できない委譲先エージェントは、loopback endpoint に限って `fastcontext` を実行してよい。
非 loopback または判定不能な endpoint では、親エージェントによる許可取得済みという申告を承認とは扱わず、対象を絞った Grep、Glob、必要ファイルの直接読み取りへフォールバックする。
それでも `fastcontext` が必要なら、メインセッションが利用者から直接許可を得て実行する。

利用者が送信先とリポジトリ内容の送信を理解したうえで当該実行をすでに明示的に依頼している場合は、同じ確認を繰り返さない。
一般的な「調べて」や「fastcontext を使って」という依頼は、外部または判定不能な endpoint へのリポジトリ内容の送信許可とは扱わない。
許可が得られなければ `fastcontext` を実行せず、理由を1行で述べ、対象を絞った Grep、Glob、必要ファイルの直接読み取りへフォールバックする。

## 問いを絞る

問いを実行する前にエンドポイントを分類し、必要な許可を得る。
挙動、境界、または症状を示し、候補位置だけを求める。
`--citation` を使い、既定では `--max-turns 1` とする。

```bash
fastcontext -q "HTTP 409 で編集が拒否されてから競合を復旧するまでのクライアント処理とテストを追跡して。" --citation --max-turns 1
```

アーキテクチャ全体の把握、作業の優先順位づけ、設計の推奨を求めない。

## 実時間の上限

探索の実時間を90秒までに制限する。
`--max-turns` はエージェントのターン数を制限するだけで、実時間の上限ではない。
実行環境の継続・終了機能を使い、上限を超えたらプロセスを止めてフォールバックする。

プロセスが完了するまで、実行結果のメタデータを保持する。

- 実行環境が継続用ハンドルやセッションIDを返したら保持して出力し、標準出力だけを取り出して捨てない。
- 終了状態が返るか90秒を超えるまで、そのハンドルをポーリングする。
- ハンドルが実行中を示している間は、空の標準出力を「検索結果なし」と解釈しない。
- 正常終了したプロセスの出力が空だった場合だけ「結果なし」と報告する。
- 同じローカルモデルに対して複数の `fastcontext` を同時実行しない。

Codex のラッパーでは、標準出力とともに継続用ハンドルも出力する。

```javascript
text(result.output);
if (result.session_id) text(`SESSION_ID=${result.session_id}`);
```

60秒近くになっても実行中なら、利用者へ短い進捗を伝える。

## 確認と返答

結果を利用する前に、挙げられたファイルを直接読む。
次の内容だけを返す。

- 候補となる実装経路または挙動の要約。
- 根拠となる `path:line`。
- 抜けや不確かな候補についての短い注記。

## フォールバック

理由を1行で述べ、対象を絞った Grep、Glob、必要ファイルの読み取りで続ける。
Explore サブエージェントは、委譲が許可されている場合だけ使う。

次の状態を区別する。

- CLI または認証情報が無い: 設定不備として報告する。
- 非 loopback または判定不能な endpoint への許可が得られない: `fastcontext` を省略したと報告し、フォールバックを使う。
- 委譲先エージェントで endpoint が非 loopback または判定不能: 親エージェントの許可申告にかかわらずフォールバックする。
- 接続拒否またはエンドポイント障害: 設定不備と断定せず、原因未確認の実行失敗として報告する。
- 90秒を超えた: 探索が実時間の上限を超えたと報告する。
- 正常終了して出力が無い: 正常終了を確認した場合だけ空結果として報告する。
