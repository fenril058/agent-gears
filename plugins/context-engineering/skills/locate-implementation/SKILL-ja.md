# Locate Implementation (fastcontext)

`fastcontext` を、読み取り専用かつ時間を制限したコード位置探索に使う。
メインエージェントが確認する候補ファイルと行範囲だけを返させ、設計や最終判断を委ねない。

## 適用条件

次の条件をすべて満たす場合だけ `fastcontext` を使う。

- 問いが具体的な挙動、障害の症状、または実行経路を自然言語で示している。
- リポジトリ固有の識別子・シンボル・パスがまだ分からず、1〜2回の対象を絞った Grep では経路を特定しにくい。
- 実装が複数のファイルまたは領域にまたがると見込まれる。
- 有用な成果物が、候補ファイルと行範囲の簡潔な一覧である。
- リポジトリが大規模または不案内で、探索中の大量の読み取りをメイン文脈から分離する価値がある。

一つでも満たさなければ Grep、Glob、必要ファイルの直接読み取りを使う。

次の用途には `fastcontext` を使わない。

- 既知ファイル、既知シンボル、エラー文字列など、正確な検索語がある。
- アーキテクチャの把握、設計評価、実現可能性の調査、issue の優先順位づけ。
- リポジトリ全体の状態や品質の評価。
- issue、Web ページ、実行時状態、ログなど、リポジトリ外の根拠が必要な問い。
- 小規模なリポジトリ、または1〜2回の検索と読み取りで答えられる問い。

## 設定

`fastcontext` は OpenAI 互換 API を使い、次の環境変数を読み、`FC_` 付きの名前を優先する。

- `FC_API_KEY` (`API_KEY`)
- `FC_MODEL` (`MODEL`)
- `FC_BASE_URL` (`BASE_URL`)

認証情報はリポジトリや Nix store に置かない。
Ollama では、空でないダミーの鍵と `http://localhost:11434/v1` のようなベース URL を使う。

初期設定時に一度だけ `fastcontext -q "test" --max-turns 1` で実エンドポイントを確認する。
通常の探索前に毎回確認せず、別の `fastcontext` が実行中のときにも起動しない。

## 問いを絞る

挙動、境界、または症状を示し、候補位置だけを求める。
`--citation` を使い、既定では `--max-turns 1` とする。

```bash
fastcontext -q "HTTP 409 で編集が拒否されてから競合を復旧するまでのクライアント処理とテストを追跡して。" --citation --max-turns 1
```

アーキテクチャ全体の把握、作業の優先順位づけ、設計の推奨を求めない。

## 実時間の上限

探索の実時間を90秒までに制限する。
`--max-turns` はエージェントのターン数を制限するだけで、実時間の上限ではない。
実行環境の継続・終了機能を使い、上限を超えたらプロセスを止めてフォールバックする。

プロセスが完了するまで、実行結果のメタデータを保持する。

- 実行環境が継続用ハンドルやセッションIDを返したら保持して出力し、標準出力だけを取り出して捨てない。
- 終了状態が返るか90秒を超えるまで、そのハンドルをポーリングする。
- ハンドルが実行中を示している間は、空の標準出力を「検索結果なし」と解釈しない。
- 正常終了したプロセスの出力が空だった場合だけ「結果なし」と報告する。
- 同じローカルモデルに対して複数の `fastcontext` を同時実行しない。

Codex のラッパーでは、標準出力とともに継続用ハンドルも出力する。

```javascript
text(result.output);
if (result.session_id) text(`SESSION_ID=${result.session_id}`);
```

60秒近くになっても実行中なら、利用者へ短い進捗を伝える。

## 確認と返答

結果を利用する前に、挙げられたファイルを直接読む。
次の内容だけを返す。

- 候補となる実装経路または挙動の要約。
- 根拠となる `path:line`。
- 抜けや不確かな候補についての短い注記。

## フォールバック

理由を1行で述べ、対象を絞った Grep、Glob、必要ファイルの読み取りで続ける。
Explore サブエージェントは、委譲が許可されている場合だけ使う。

次の状態を区別する。

- CLI または認証情報が無い: 設定不備として報告する。
- 接続拒否またはエンドポイント障害: 設定不備と断定せず、原因未確認の実行失敗として報告する。
- 90秒を超えた: 探索が実時間の上限を超えたと報告する。
- 正常終了して出力が無い: 正常終了を確認した場合だけ空結果として報告する。
