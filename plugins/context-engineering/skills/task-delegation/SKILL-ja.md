# タスク委譲ポリシー

委譲するかどうかは、モデル価格ではなくタスクの独立性で決める。
サブエージェントがメインセッションへ繰り返し確認せずに区切られた作業を完了でき、メインセッションが簡潔な報告や差分から結果を検証できる場合に委譲が役立つ。

この skill 自体は委譲を許可しない。
現在のホストがサブエージェントへの委譲を許可した後にだけ使い、そのホストの起動許可に関する規則に従う。

委譲の許可と、委譲の要求は異なる。
ユーザーの要求または実行中の手順にある指示によって委譲が要求される場合があるが、その要求はホストによる許可に代わるものではない。
ホストが起動許可に関する規則をコストの観点から示している場合も、その規則が委譲を実行できるかどうかを決める。
委譲が許可されていても明示的に要求されていない場合、タスクの独立性と委譲コストを基準に委譲するか判断する。
委譲が許可され、かつ明示的に要求されている場合、メインセッションで作業する方が低コストであることだけを理由に取り消さない。
要求の制約内で、委譲する範囲、agent type、起動数、既存 agent の継続と新規 spawn のどちらにするか、委譲文の内容はこの skill で判断する。

## メインセッションに残す判断

作業の方向を決める仕事と、結果を受け入れる仕事はメインセッションに残す。

- 問題の分割と優先順位の決定
- 設計または実装方針の選択
- 曖昧さの解消と、影響の大きいトレードオフの判断
- 返された作業のレビューと完了判定
- 最終回答

セカンドオピニオンも判断を求める作業である。
タスクの委譲先ではなく、`subagent-consultation` を使う。

## 独立した作業を委譲する

作業を始める前に範囲、入力、受け入れ条件を定められ、継続的な調整なしに結果を統合できる場合、その作業を委譲できる。
典型的な対象は次のとおり。

- 正しさを直接検証できる機械的または反復的な編集
- メインセッションが結論と出典だけを必要とする、読み取り量の多い広域探索
- 設計、インターフェース、受け入れ条件が確定している独立した実装

独立性と難易度は別の性質である。
作業を遂行できるサブエージェントを選び、モデル価格は委譲基準ではなく実装上の副次的な選択として扱う。

## 委譲コストを見積もる

ここでいう委譲コストは、サブエージェントへ作業を渡して結果を統合するまでに必要な費用と作業時間を指す。
委譲が許可されているだけで明示的に要求されていない場合、委譲コストがメインセッションで作業するコストを上回る見込みなら委譲しない。
モデル価格だけでなく、次の負担を含めて判断する。

- サブエージェントによる関連文脈の再構築
- ツールの起動と作業環境の準備
- 確認、調整、再実行
- 結果のレビューと統合

短時間で終わる作業、現在の判断と密接に結び付いた作業、メインセッションがすでに十分な文脈を持つ作業はメインセッションに残す。
委譲が明示的に要求されている場合、総コストは委譲を取り消す唯一の理由にせず、委譲の構成と範囲を調整する基準として使う。
価格やレート制限は、独立性と委譲コストを検討した後の同程度の選択肢を比べる場合にだけ使う。

## 委譲文を書く

委譲文には次の3項目を必ず指定する。

- **Scope**：扱うファイル、構成要素、問い。除外対象も含める。
- **Deliverable**：完成すべき成果と、その受け入れ条件。
- **Output Format**：差分、出典付き要約（`path:line`）、変更ファイルとテスト結果の一覧など、返答の形式。

調査過程の逐語的な報告ではなく、結論と根拠だけを返すよう指示する。
区切られた作業の完了に必要な文脈だけを渡す。
未解決の設計判断や対象範囲外の作業が見つかった場合、サブエージェントにはその部分を進めず、必要な判断を報告させる。

例：

> Scope：レート制限の実装箇所を、ミドルウェア、設定、カウンタを含めて特定する。ファイルは編集しない。
> Deliverable：方式、設定された制限値、適用範囲を、メインセッションがレビューできる根拠とともに説明する。
> Output Format：`path:line` 形式の出典を付けた簡潔な結論。調査過程やソース全文は含めない。

## レビューして統合する

結果の検証はメインセッションが担当する。
出典または差分を確認し、リスクに応じた検査を実行し、ほかの作業との競合を解消して、最終判断を行う。

## プラットフォームごとの注意

現在のホストが提供するサブエージェントの仕組みを使い、起動の許可に関する規則に従う。
ツール名とモデル上書きの対応状況はホストやビルドによって異なるため、特定のインターフェースを仮定せず、実行環境から確認する。

このリポジトリは、機械的編集用の `bulk-edit` と広域探索用の `search` を提供する。
両者はタスクの性質によって役割を分けており、設定されたモデルはプラットフォーム実装の詳細である。
